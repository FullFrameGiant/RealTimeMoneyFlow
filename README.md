# 即時資金流（shioaji 版）

盤中即時顯示各族群「開盤至今的主動買賣淨額」，畫面仿照分歧河道動畫：

- **主動買賣淨額 = 外盤成交金額 − 內盤成交金額**（逐筆 Tick 的 `tick_type`：1 外盤、2 內盤、0 無法判定）
- 柱長用開根號比例（大族群不會把小族群壓扁），**河道粗細 = 成交額**
- 粒子方向 = 最近一分鐘的資金方向：往外流代表同向加碼，往內流代表開始反向
- 右上「排序」按鈕：預設「漲→跌」（資金入→出），點一下變「跌→漲」（資金出→入），再點切回
- 每列右邊的資金欄會輪播：資金 → 第 1 名 → 第 2 名 → 第 3 名，各 5 秒。資金流入的族群輪播漲幅前三名，流出的族群輪播跌幅前三名（成分股不到 3 檔的族群只在有的項目之間輪流，例如只有 1 檔就是「資金 → 該股 → 資金 → 該股」，不會出現空檔）
- 族群前面的點點：成分股平均漲幅 ≥ +4% 紅色、平均跌幅 ≤ −4% 綠色，其他維持原本顏色（電子黃、傳產紫、金融藍）
- 「全市場」卡片多一行「總量」＝外盤金額＋內盤金額（主動成交總額），並與「昨日」（前一個有錄製的交易日，週末假日自動跳過）「同一時間」比較，例如 10:30 時是今天到 10:30 對比前一交易日到 10:30（前一交易日沒錄製就顯示「昨日無資料」；舊錄製檔沒有總進出時兩天都改用成交額比較）
- 上方三張卡片：全市場主動淨額、加權指數、上櫃指數（紅漲綠跌）。指數每 5 秒用快照更新一次（`[estimate] index_interval`），也會錄進回放
- 點族群可以看成分股：漲跌幅、主動淨額、成交額，預設依漲跌幅排序，點表頭可切換；即時模式下開著會自動更新
- 時間軸可拖曳回看；每天自動存檔可回放

## 安裝

需要 Python 3.9 以上。

```
pip install shioaji openpyxl
```

把 `config.example.ini` 複製成 `config.ini`（`start.bat` 第一次執行會自動複製）。範例設定已經指向：

- 金鑰：`key_file = C:\Users\Giant\.spyder-py3\user_config.json`（跟 monitor_bot 共用同一個金鑰檔，不用再抄一份）
- 族群：`group_file = C:\Users\Giant\.spyder-py3\stocks.txt`

也可以直接在 `api_key` / `secret_key` 填，或設環境變數 `SJ_API_KEY`、`SJ_SEC_KEY`。

## 使用流程

| 時間 | 指令 | 說明 |
|---|---|---|
| 第一次 | `python tests/test_all.py` | 不用帳號的自我測試（49 項） |
| 第一次 | `python server.py --sim`（或雙擊 `start_sim.bat`） | 用假行情 + 你的 stocks.txt 族群看畫面（20 倍速） |
| 第一次（盤中） | `python check_env.py` | 檢查登入、族群檔、覆蓋率，並驗證內外盤累計量方向 |
| 每天 08:50 前 | `python server.py`（或雙擊 `start.bat`） | 實盤，瀏覽器會自動開 http://127.0.0.1:8765 |
| 收盤 13:40 後 | `python build_replay.py` | 抓全市場逐筆，做一份 100% 精確的回放 |
| 任何時候 | `python server.py --view` | 不連線，只看存檔回放 |

**建議開盤前就啟動**。中途才啟動也可以，程式會用 Tick 裡的「累計外盤量／內盤量 × 均價」把啟動前的部分估回來，但那段是估算值。

## 回放

| 想看什麼 | 怎麼做 |
|---|---|
| 盤中看今天稍早的變化 | 按「▶ 今日回放」從 09:00 開始播，播到最新會自動接回即時；或直接拖時間軸，按「回到即時」回來 |
| 收盤後、隔天看今天 | 雙擊 `start_view.bat`（不登入 shioaji、不切電源、不關機），下拉選單選日期 |
| 13:40 關機後，晚上用手機看 | 開機 → 雙擊 `start_view.bat` → 手機打開原本的 Funnel 網址。Tailscale 會隨 Windows 自動啟動，`tailscale funnel --bg` 的設定重開機後仍有效，密碼保護也照常 |
| 實盤執行中看以前的日子 | 下拉選單選日期 |

**存檔與容量**：程式每次啟動會整理 `data/`：只保留最近 `keep_days`（預設 4）個有實盤錄製的交易日（模擬檔不佔名額，只在「今天」或「跟保留的實盤同一天」時留著），今天以前的錄製壓縮成 `.json.gz`（約剩 1/3），前幾天的 `.state.json` 刪除。設定在 `config.ini` 的 `[data]`。

每天的資料存在 `data/日期.live.json`（盤中錄製，每分鐘一格，成分股明細與漲跌幅每 5 分鐘一筆）。收盤後跑 `build_replay.py` 會多一份 `日期.full.json`（全市場逐筆精算版），下拉選單會優先列出。

## 族群檔

在 `config.ini` 的 `group_file` 指定路徑。有族群檔時畫面上方會有「我的族群／產業別」兩個頁籤：「我的族群」看你自己的分類，「產業別」看全市場（跟原影片一樣）。全市場合計兩頁相同。

### stocks.txt（你現有的格式，直接用）

規則與 `quant_system/monitoring/parsers.py` 相同：

```
TOP_CLASS=031,042,100          ← 重點分類，畫面上族群名稱後面加 ★
TOP_STOCK=2330,6488,5483       ← 重點個股，成分股明細加 ★
###031:CPO矽光子射頻           ← 3 個 # = 分類定義
2330台積電:001,120             ← 股票：所屬分類代碼
#3661世芯-KY:010,011           ← 1 個 #：照檔頭規則「盤中仍看所屬分類」，預設納入（include_commented）
## 封裝/測試 ##                ← 2 個 # 忽略
```

一檔屬於多個分類（例如 2330 同時在「上市七大」與「台積電概念」）時，金額會完整計入每個分類。目前檔案是 43 個分類、167 檔（其中 92 檔前面有 #）。

**訂閱順序**：族群檔裡的股票優先訂閱逐筆（`subscribe_priority = groups`），剩下的名額再依成交額補滿。167 檔用 1 個連線（200 檔）就裝得下，所以「我的族群」那頁每一檔都是逐筆精算；畫面底部會寫「我的族群 167 檔中 167 檔為逐筆精算」。monitor_bot 盤中也會佔一個連線，兩支同時跑沒問題（上限 5 個）。

改了 stocks.txt 之後重開程式就會生效。

### 其他格式（自動判斷）

**長表**（每列一檔，族群可以多個）：
```
代號,名稱,族群,大類
2330,台積電,AI晶片、CoWoS,電子
2382,廣達,AI伺服器,電子
2881,富邦金,金控,金融
```
「大類」可省略，用來決定圓點顏色（電子＝黃綠、傳產＝紫、金融＝藍）；省略時依成分股的產業別自動判斷。

**寬表**（每欄一個族群，底下列成員）：
```
AI伺服器,散熱,CoWoS
2382 廣達,3017 奇鋐,2330
3231 緯創,3324 雙鴻,3131
```

**JSON**：`{"AI伺服器": ["2382", "3231"], "散熱": ["3017"]}`

CSV 可以是 UTF-8 或 Big5（cp950），Excel 也行。一檔股票屬於多個族群時，它的金額會完整計入每個族群；全市場合計只算一次。

族群檔沒涵蓋的股票，由 `unassigned` 決定：`industry` 歸到產業別、`other` 歸「未分類」、`drop` 不顯示（仍計入全市場）。

## 資料怎麼來、準確度

shioaji 每個連線最多訂閱 200 檔（同一身分證最多 5 個連線），全市場普通股約 1,800 檔訂不完，所以分兩層：

1. **成交額前 N 檔：逐筆 Tick 精確累加**。N = `connections × per_connection`。程式開盤前用快照依昨日成交額排序挑選。`check_env.py` 會印出前 200／400／600／1000 檔各占全市場成交額幾成，可以依此決定要開幾個連線。
2. **其餘股票：快照估算**（`snapshot_interval` 秒一次）。兩次快照之間的成交額變化，價格上漲算外盤、下跌算內盤、平盤看最後一筆的內外盤。這是近似值，畫面底部會顯示估算部分占成交額多少。

收盤後跑 `build_replay.py` 會用 `api.ticks` 抓每一檔的整天逐筆重算，得到不含任何估算的版本（回放選單裡標「盤後逐筆」）。

### 官方使用限制（程式已遵守）

- 訂閱：每連線 200 檔；同一身分證最多 5 個連線。開了多個連線，其他程式（例如你的下單程式）可用的連線就變少。
- 查詢（快照、ticks、kbars）：10 秒內合計最多 50 次，程式節流在每 0.25 秒一次。
- **盤中 `ticks` 查詢不得超過 10 次**，所以 `build_replay.py` 在 08:30–13:40 之間會拒絕執行。
- 流量：訂閱推播不計流量；查詢依近 30 日 API 成交額，每日 500MB／2GB／10GB。盤中快照估算一天約用 100–200MB；`build_replay.py` 抓全市場一次可能要數百 MB，程式每 100 檔檢查一次 `api.usage()`，剩不到 30MB 就先停（依成交額由大到小抓，所以停下來時大的都已經抓到）。

## 用手機／在外面看

程式本身（要登入 shioaji 的那部分）得在一台開著的電腦上跑，手機只是開網頁。所以重點是「讓手機連得到你電腦上的 8765 埠」。比較過的做法：

| 做法 | 費用 | 誰看得到 | 適合 |
|---|---|---|---|
| **Tailscale（推薦）** | 免費（個人方案最多 6 人、裝置不限） | 只有登入你帳號的裝置 | 自己用、家人用 |
| Cloudflare Tunnel | 免費；固定網址需要自己的網域 | 拿到網址的人（請設 `password`） | 要給沒裝 App 的人看 |
| ngrok（你 monitor_bot 用的） | 免費方案每月 2 萬次請求 | 拿到網址的人 | **不建議**：這個網頁每天會打 8,000～16,000 次請求，一兩天就把額度用完，連帶 monitor_bot 的 Telegram webhook 也會停 |
| 雲端主機（VPS） | 約每月 US$5–10 | 依設定 | 不想讓家裡電腦開著 |

### Tailscale 設定（約 10 分鐘，一次就好）

1. 電腦裝 Tailscale（Windows 版），用 Google 帳號登入。
2. 手機裝 Tailscale App，用同一個帳號登入。
3. 電腦開命令列執行一次：
   ```
   tailscale serve --bg localhost:8765
   ```
   會顯示一個網址，長得像 `https://你的電腦名.xxxx.ts.net/`。第一次可能會要你到管理頁面打開 HTTPS，照提示按一下即可。`--bg` 會記住設定，電腦重開也有效；要關掉用 `tailscale serve reset`。
4. 手機打開那個網址，用瀏覽器「加入主畫面」，之後點圖示就能看。

`config.ini` 的 `host` 維持 `127.0.0.1` 就好，不用開防火牆。只有你帳號的裝置連得到，密碼可設可不設。

### 開機自動跑

在你的 `x_ForStock.bat` 加一段（路徑改成你解壓縮的位置）：

```
:: 即時資金流
start "MoneyFlow" %WINDIR%\System32\cmd.exe /K "C:\Users\Giant\anaconda3\Scripts\activate.bat C:\Users\Giant\anaconda3 && cd /d C:\Users\Giant\moneyflow && python server.py --no-browser"
```

shioaji 一人最多 5 個連線，monitor_bot 一個、這支一個，綽綽有餘。13:35 後這支會自動登出釋放連線，網頁還是開著可以回放。

### 手機流量

資料有 gzip 壓縮、手機每 2 秒更新一次、只傳目前頁籤的族群，螢幕關掉或切到別的 App 時會暫停。整個盤中一直開著看，大約用 13MB。想更省可以在網址後面加 `?poll=5`（每 5 秒更新）。

### 放到雲端主機

程式在 Linux 上可以跑（shioaji 有 Linux 版），而且已經固定使用台灣時間，不受主機時區影響。注意兩件事：金鑰會放在雲端主機上；主機要在 08:45～13:40 開著（可以用排程開關機省錢）。對外開放時務必設 `password`，並放在 HTTPS（Cloudflare Tunnel 或 Caddy 反向代理）後面。Python 內建的 HTTP 伺服器不適合直接裸露在網路上。

## 省電計畫與自動關機（Windows）

執行 `start.bat` 或 `start_sim.bat` 時：

1. 先記下電腦目前的電源計畫（例如「平衡」），存在 `data/power_restore.json`
2. 切換成「省電」計畫。有些電腦把省電計畫藏起來了，程式會從 Windows 內建範本補建一個
3. 執行期間不讓電腦進入睡眠（螢幕仍會照設定關閉），避免睡著後收不到行情、手機連不到
4. 結束時先還原原本的電源計畫，再結束程式。正常結束、按 Ctrl+C、按視窗右上角的 X、登出 Windows 都會還原
5. 當天 13:40 程式還在執行的話：還原電源計畫 → 存檔 → 登出 shioaji → 倒數 60 秒關機

**關機注意**：倒數時 Windows 會強制關閉所有程式，Spyder、記事本裡沒存的東西會不見。倒數期間在命令提示字元執行 `shutdown /a` 可以取消。13:40 之後才啟動的話，當天就不排關機。13:40 關機也代表盤後的 `build_replay.py` 不會跑；盤中錄製版仍會存檔，可以回放。

用工作管理員強制結束程式、或停電時，程式來不及還原。下次啟動會自動以存檔的原計畫為準，也可以雙擊 `restore_power.bat` 立刻還原。

相關設定在 `config.ini` 的 `[power]`：`power_saver`、`keep_awake`、`shutdown_at`（留空＝不關機）、`shutdown_countdown`。

## 設定檔重點

| 參數 | 預設 | 說明 |
|---|---|---|
| `connections` | 1 | 用幾個連線訂閱 Tick（1–5） |
| `snapshot_interval` | 60 | 尾端股票快照估算間隔，0＝不估算 |
| `repair` | true | 中途啟動／斷線重連時用累計外內盤量補值 |
| `side_swap` | false | 只有在 `check_env.py` 說方向相反時才改 |
| `auction_neutral` | true | 開盤、收盤集合競價的成交只算成交額、不算主動買賣（改 false＝照 shioaji 標的內外盤計入） |
| `host` | 127.0.0.1 | 用 Tailscale serve 時維持不變；改 `0.0.0.0` 可在同一個 Wi-Fi 下直接用電腦 IP 看 |
| `password` | （空） | 設了就需要帳號密碼才能看（帳號 `username`，預設 me） |
| `poll_seconds` | （空） | 網頁多久向電腦要一次資料。空＝電腦 1 秒、手機 2 秒；設 15 只省手機流量，電腦端計算不受影響 |
| `anim_fps` | 30 | 動畫每秒張數，越低越省電（看網頁的那台裝置） |

網址參數：`?n=10` 每邊顯示 10 個族群；`?date=2026-10-20` 直接回放某天；`?set=industry` 直接開產業別；`?poll=5` 每 5 秒更新；`?fps=60` 動畫 60 張。

## 已知限制

- 2026-11-03 實盤驗證：shioaji Tick 的 `bid_side_total_vol` 是**買盤（外盤）**累計、`ask_side_total_vol` 是賣盤（內盤）累計（200 檔中 199 檔與逐筆 tick_type 累加方向一致）。程式已依此處理中途啟動補值；`side_swap` 維持 false。

- 我這邊沒有辦法連到永豐的伺服器，shioaji 介接是依官方文件撰寫，並用模擬新舊兩版介面的假模組測過所有流程；第一次請先跑 `check_env.py` 確認。
- 開盤、收盤集合競價沒有主動的一方，程式只把它算進成交額、不算進主動淨額（`auction_neutral = true`）。2026-11-03 實測 shioaji 仍會把這兩種成交標成外盤或內盤（當天逐筆訂閱的股票裡，收盤撮合量較大的 104 檔有 62 檔被標外盤、42 檔標內盤、0 檔標無法判定；照標記計入的話，13:30 那一格全市場淨額會一口氣跳約 +290 億），所以程式自己辨認：每檔今天第一筆且在 09:05 前＝開盤撮合；13:25 之後的成交＝收盤撮合。
- 中途啟動時用交易所累計外內盤量補回的早盤部分，會含開盤撮合被標的方向（無法拆開），影響很小。
- 2026-11-03 的錄製是在上述修正前錄的：09:00～09:02 的成交額因為混入前一天的快照數字而偏高、13:30 那格含收盤撮合的方向。這份檔案 4 個交易日後會自動清掉；拿它當「昨日」比較總量時，程式會自動濾掉開盤的虛高。
- 快照估算對小型股是粗估；盤中想要更準就增加連線數，或以盤後逐筆版為準。
